[2] 前置调研：appDb 的可注入性
--------------------------------------------------
现状：val appDb by lazy { Room.databaseBuilder(appCtx, ...).build() }

引用面统计：827 处，分布在 154 个文件。
结论：不能直接把 appDb 参数化，否则 827 处调用点全要改。

方案：把实现搬到 DbProvider，保留 `val appDb: AppDatabase get() = DbProvider.db`。
      访问器名字不变 → **827 处调用点零改动**，diff 集中在 AppDatabase.kt。

[3] 实现改动
--------------------------------------------------
AppDatabase.kt：
  - 新增 object DbProvider：持有 defaultDb（lazy）与 overridden（测试注入）
    - db: AppDatabase  —— overridden ?: defaultDb
    - override(database) / reset()  —— 均标注 @VisibleForTesting
  - val appDb: AppDatabase get() = DbProvider.db   —— 保留原访问器
  - 新增 abstract class TestableCallback : RoomDatabase.Callback()
    - 内含 @VisibleForTesting val skipSeedData: Boolean
    - onOpen 开头 `if (skipSeedData) return`

  为什么需要 TestableCallback：
    Kotlin 对 `object : Callback() { var x }` 会把类型推断成匿名类型，
    成员在外部不可见，测试写不出 AppDatabase.dbCallback.skipSeedData。
    显式继承命名类即可暴露。
    （首次实现时踩了这个坑，编译报 Unresolved reference 'skipSeedData'。）

app/build.gradle：
  - testImplementation(libs.robolectric)      // org.robolectric:robolectric:4.14.1
  - testImplementation(libs.room.testing)     // 复用已有的 room-testing 版本 2.7.1
  - testOptions { unitTests { includeAndroidResources = true } }

gradle/libs.versions.toml：
  - robolectric = { module = "org.robolectric:robolectric", version = "4.14.1" }

app/src/test/java/io/legado/app/testing/TestApplication.kt：
  - 空壳 Application，仅供 Robolectric 使用

[4] 环境障碍与处理（三次失败）
--------------------------------------------------
障碍 1：Robolectric 运行时下载极慢
  现象：首次运行 testAppDebugUnitTest 卡在配置阶段超过 30 分钟无输出。
  排查：gradlew :app:help 与 :app:dependencies 均 10~20s 正常，排除配置问题。
  定位：Robolectric 首次运行需下载 android-all-instrumented（约 156MB），
        官方 Maven 实测约 30 KB/s，需一小时以上。
  处理：手动预下载到 ~/.m2/repository/org/robolectric/android-all-instrumented/
        13-robolectric-9030017-i7/（SDK 33 对应版本）。
        改用阿里云镜像 https://maven.aliyun.com/repository/public，
        实测 23 秒完成，文件 155.7 MB，解压校验 66508 个条目完整。

障碍 2：skipSeedData 无法解析
  现象：e: Unresolved reference 'skipSeedData'
  原因：匿名 object 的类型推断问题（见 [3]）
  处理：抽出 TestableCallback 基类

障碍 3：Robolectric 下应用初始化崩溃
  现象：ExceptionInInitializerError at App.kt:296
        Caused by: IllegalStateException at AppCtx.kt:40
  原因：Robolectric 默认使用清单里声明的 io.legado.app.App，
        其 onCreate 会做 CrashHandler、网络监听、协程、通知渠道、Cronet 等初始化，
        其中依赖 splitties 的 appCtx，在单测环境不可用。
  处理：@Config(application = TestApplication::class)，用空壳 Application。
        不引入新的测试依赖（未用 androidx.test.core 的 ApplicationProvider，
        改用 Robolectric 自带的 RuntimeEnvironment.getApplication()）。
