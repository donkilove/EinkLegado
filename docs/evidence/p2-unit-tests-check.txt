[4] 发现并修复一个真实缺陷
--------------------------------------------------
现象：3 个用例抛 StringIndexOutOfBoundsException
  空串输入          → String index out of range: 0
  纯空白输入        → String index out of range: 3
  单个分隔符 "@"    → String index out of range: 1

定位：RuleAnalyzer.trim()（原第 15-22 行）
  fun trim() {
      if (queue[pos] == '@' || queue[pos] < '!') {
          pos++
          while (queue[pos] == '@' || queue[pos] < '!') pos++
          ...
      }
  }
  两处越界：
    a) 空串时 queue[pos] 直接越界；
    b) 整串都是 @ 或空白时，while 循环会把 pos 推到 length 之外再取 queue[pos]。

影响：任何把空串或纯空白传给 RuleAnalyzer 的调用方都会崩溃。
      书源规则里空规则并不罕见（用户没填某一级规则、模板渲染出空值）。

修复：
  fun trim() {
      if (pos >= queue.length) return
      if (queue[pos] == '@' || queue[pos] < '!') {
          pos++
          while (pos < queue.length && (queue[pos] == '@' || queue[pos] < '!')) pos++
          ...
      }
  }

说明：这是**行为变更**（原来崩溃，现在安全返回）。
      按用户授权「允许顺带修 bug」执行，并在此记录。

[5] 一次断言写错（非代码缺陷）
--------------------------------------------------
修复越界后又有一个失败：
  `纯分隔符被 trim 全部跳过返回空列表`
  expected 空列表，实际返回 [""]

用临时探针跑了 9 组边界输入，确认实际行为：
  INPUT=[]        -> size=1 parts=[[]]
  INPUT=[ ]       -> size=1 parts=[[]]
  INPUT=[@]       -> size=1 parts=[[]]
  INPUT=[@@@]     -> size=1 parts=[[]]
  INPUT=[  @  ]   -> size=1 parts=[[]]
  INPUT=[a@]      -> size=2 parts=[[a], []]
  INPUT=[@a]      -> size=1 parts=[[a]]
  INPUT=[  a  ]   -> size=1 parts=[[a  ]]

判定：**我的断言写错**（以为是空列表，实际是单元素空串），代码行为自洽。
处理：修正断言，并补充 3 条边界用例把这个行为钉住。
      探针测试用完即删，不保留在仓库。
