[2] 实现中发现并修正的两个隐患
--------------------------------------------------
隐患 A：底栏菜单项按下标访问会错位
  原代码 MainActivity.kt:501
    binding.bottomNavigationView.menu[realPositions[position]].isChecked = true
  realPositions 存的是逻辑 id（书架 0 / 发现 1 / 订阅 2 / 我的 3），
  历史上恰好与 main_bnv.xml 中菜单项的顺序一致，所以用下标碰巧正确。
  插入「搜索」后 menu_discovery 从索引 1 变 2、menu_rss 从 2 变 3、
  menu_my_config 从 3 变 4，巧合失效，会勾错菜单项。

  修正：新增 menuItemIdOf(logicalId) 显式映射，改用
        menu.findItem(id)?.isChecked = true

隐患 B：realPositions 残留旧值
  upBottomMenu() 只填充不清空。若先开启某开关再关闭，数组里会留下上次的 id，
  getFragmentId() 可能返回一个已不存在的页面，导致切页空白或错位。

  修正：填充前 realPositions.fill(idBookshelf)

--------------------------------------------------
[3] 一处默认值决策
--------------------------------------------------
AppConfig.showSearchPage 的代码默认值取 true，与 pref_config_other.xml 的
defaultValue="true" 保持一致。

不沿用 showDiscovery / showRSS 的写法（代码默认 false、靠 XML 首次写入 true）：
首次安装时那三个键并不存在于 SharedPreferences，getPrefBoolean 会返回代码默认值。
实测发现 showDiscovery / showRSS 在全新安装的模拟器上确实不显示（底栏只有书架+我的），
这是既有行为、不是本次引入的。但搜索入口是新功能，若默认不显示会让人以为功能不存在，
所以这里选 true。
