--------------------------------------------------
[1] 三个开关
--------------------------------------------------
| 开关 | key | 默认 | 作用 |
|---|---|---|---|
| 同步阅读时长 | syncReadRecord | true | 参与同步载荷 |
| 自动上传本地书 | autoUploadLocalBook | false | 导入本地书后自动上传并转为 WebDAV 书 |
| 按需下载 WebDAV 书 | autoDownloadWebDavBook | true | 本地无文件时阅读前自动下载 |

自动上传默认关闭：上传会把书推到云端并改写 origin，属于有副作用的动作，
不该在用户没表态时自动发生。
按需下载默认开启：这是 WebDAV 书能正常阅读的前提，关掉等于书打不开。

[3] 关键设计：开关关闭时给 null，不是空列表
--------------------------------------------------
关闭「同步阅读时长」时，载荷里 readRecords 必须是 null：
  null → 本次载荷不携带该类目，同步整体跳过，不动任何一端
  []   → 云端确认「一条阅读记录都没有」，会按删除传播清掉对方的记录

抽成 SyncPayloadGate 纯函数，就是为了让这个 null / [] 的选择能被单测钉住。
另外整个表达式用 runCatching 兜底：读配置或读表失败时同样给 null，
绝不能让一次读取失败变成「云端确认没有」而删掉别的设备的数据。

--------------------------------------------------
[4] 按需下载关闭时的提示
--------------------------------------------------
原实现：本地无文件且是 WebDAV 书 → 尝试下载 → 失败则抛「文件不存在」。
关闭开关后若仍走原路径，用户会看到「文件不存在」，
但文件其实在云端，只是被设置拦住了——这是误导。

现在：开关关闭时直接抛「按需下载已关闭，且本书本地没有文件」，
让用户知道是设置问题而不是数据丢失。

--------------------------------------------------
[5] 自动上传的挂载点
--------------------------------------------------
LocalBook.importFile(uri) 在新建书籍并入库后调用 autoUploadIfNeeded(book)：
  - 开关关闭 → 直接返回，无任何网络请求
  - 未配置 WebDAV → 直接返回
  - 否则异步上传，成功后 RemoteBookWebDav.upload 把 origin 改成 webDav::<url>
失败只记日志，不打断导入——用户的本意是把书导进来，上传是附加动作。

[7] 模拟器实测
--------------------------------------------------
WebDav 设置页共 10 项，分 2 页（墨水屏分页）：
  第 1 页：服务器地址 / 账号 / 密码 / 子目录 / 设备名称 /
           同步阅读进度 / 同步增强 / **同步阅读时长（默认开）**
           → 截图 webdav-sync-v3-switches-1.png
  第 2 页：**自动上传本地书（默认关）** / **按需下载 WebDAV 书（默认开）**
           → 截图 webdav-sync-v3-switches-2.png

点击「按需下载 WebDAV 书」关闭后读 SharedPreferences：
  name="autoDownloadWebDavBook" value="false"
  name="syncReadRecord" value="true"
  name="autoUploadLocalBook" value="false"
即开关状态正确持久化，且三个默认值与设计一致。
