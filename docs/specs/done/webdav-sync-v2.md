# WebDav 同步 v2：聚合进度同步与多数据同步

状态：done（归档 2026-11-23）
创建：2026-11-21

## 目标

解决三件事：

1. **打开 App 就能续读**：不再需要逐本进入阅读界面才同步。打开 App、切到书架、或手动刷新时，一次性对齐所有书的阅读进度，点开任何一本直接续读。
2. **进度不丢**：章节切换、退出阅读界面都触发上传；网络恢复时补传。
3. **同步范围扩大**：阅读设置、书签、书架分组、书源一并同步，换设备后不用整包备份恢复。

## 冲突规则

**取最远位置**（与用户实际需求一致）：

- 同一本书比较 `durChapterIndex`，更大者胜；章节相同则比较 `durChapterPos`。
- 进度只前进、不后退。
- 云端更新的进度在同步时**静默应用**到本地图书记录，不弹窗询问。

## 范围

### 阶段 A：进度聚合（本次）

| 项 | 设计 |
|---|---|
| 存储 | 单一 `progress.json`，内含所有书的进度条目 |
| 下载 | 启动 / 切到书架 / 手动刷新时各触发一次，一次请求拿全量 |
| 合并 | 逐本比较，取章节索引更大者，写回本地 `Book` 记录 |
| 上传 | 章节切换、退出阅读界面时更新聚合文件对应条目并上传 |
| 反馈 | 有实际变更时提示「已同步 N 本书进度」；无变更时不打扰 |
| 手动入口 | 书架下拉刷新触发同步（复用现有刷新手势） |
| 迁移 | 首次升级时把旧的「每本一个文件」格式合并为聚合文件，完成后保留旧文件不再读写 |

### 阶段 B：扩展数据（已完成）

| 数据 | 存储 | 合并策略 | 状态 |
|---|---|---|---|
| 阅读设置 | `readConfig.json` + `shareReadConfig.json` | 以文件修改时间判新旧，云端更新则覆盖本地并重新加载 | ✅ |
| 书签 | `syncData.json` 内 | 按 `书名\|作者\|章\|位置` 去重 | ✅ |
| 书架分组 | `syncData.json` 内 | 按 `groupId` 去重 | ✅ |
| 书源 | `syncData.json` 内 | 按 `bookSourceUrl` 去重 | ✅ |

**合并语义为「最后修改者胜」**（2026-11-21 修正）：

最初采用「只增不删」，但用户删除书签/分组后，下次同步会被云端补回，删除永远无法传播（已实测复现）。现改为：

- `SyncState` 记录上次同步完成时的数据指纹；
- 本地指纹与记录一致 ⇒ 本地没动过 ⇒ 以云端为准**整体替换本地**（删除可传播下来）；
- 本地改过 ⇒ 上传本地（删除可传播上去）；
- 两端都改过 ⇒ 以本地为准；
- **书源保护**：一端书源为空而另一端有数据时，不用空列表覆盖，避免误删资产。

同步入口：`syncData.json`（分组/书签/书源）与排版文件在**启动**和**书架下拉刷新**时同步；切到书架只对齐阅读进度，避免频繁传输大文件。

## 非目标

- 不同步书籍文件本身（TXT/EPUB 内容）。
- 不做实时长连接推送（电纸书续航优先）。
- 不改变 WebDav 账号与目录结构的基本约定。

## 风险

- 单文件随书架增长变大（100 本约 30 KB，可接受；千本级需分片）。
- 两台设备同时上传可能互相覆盖；交替使用场景下影响有限。
- 迁移过程若中断，需保证旧文件不被删除，可重试。

## 决策记录（完成后追加）

- 决策日期：2026-11-23（归档时补写；各阶段完成时间见变更记录）
- 决策：
  1. 冲突规则为「取最远位置」：比较 `durChapterIndex`，相同再比 `durChapterPos`，进度只前进不后退。
  2. 进度聚合为单一 `progress.json`，不再每本一个文件。
  3. 用户数据（分组/书签/书源）的合并语义由「只增不删」改为「最后修改者胜」。
  4. 书源有一条不对称保护：一端书源为空而另一端有数据时，不用空列表覆盖。
  5. 同步时机：启动与书架下拉刷新走全套；切到书架只对齐阅读进度。
- 理由：
  1. 与用户实际需求一致；进度倒退是明确的坏体验。
  2. 打开 App 全量对齐要发 N 次请求（实测 58 本 → 58+ 次），聚合后降为 3 次。
  3. 「只增不删」下用户删除的书签下次同步会被云端补回，删除永远无法传播（已实测复现）。改用 `SyncState` 记录上次同步指纹，由改动过的一端覆盖另一端。
  4. 首次安装或数据损坏时本地书源可能为空，用空列表上传会冲掉云端书源。
  5. 排版配置与同步数据文件较大，切书架时频繁传输不值得。
- 被放弃的备选：
  - 「只增不删」合并——删除无法传播，已实测证伪。
  - 实时长连接推送——电纸书续航优先。
  - 同步书籍文件本身（TXT/EPUB 内容）——体积过大，不在同步范围内。
- 未达成的 AC：无。AC-1 ~ AC-7 全部通过，证据见 `docs/evidence/eink-only-check.txt` 的 [18]、[18b]、[18c]、[19]、[19b]、[19c] 段。
