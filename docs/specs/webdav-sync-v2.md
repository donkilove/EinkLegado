# WebDav 同步 v2：聚合进度同步与多数据同步

状态：进行中
创建：2026-11-21

## 目标

解决三件事：

1. **打开 App 就能续读**：不再需要逐本进入阅读界面才同步。打开 App、切到书架、或手动刷新时，一次性对齐所有书的阅读进度，点开任何一本直接续读。
2. **进度不丢**：章节切换、退出阅读界面都触发上传；网络恢复时补传。
3. **同步范围扩大**：阅读设置、书签、书架分组、书源一并同步，换设备后不用整包备份恢复。

## 冲突规则

**取最远位置**（与用户实际需求一致）：

- 同一本书比较 `durChapterIndex`，更大者胜；章节相同则比较 `durChapterPos`。
- 进度只前进、不后退。
- 云端更新的进度在同步时**静默应用**到本地图书记录，不弹窗询问。

## 范围

### 阶段 A：进度聚合（本次）

| 项 | 设计 |
|---|---|
| 存储 | 单一 `progress.json`，内含所有书的进度条目 |
| 下载 | 启动 / 切到书架 / 手动刷新时各触发一次，一次请求拿全量 |
| 合并 | 逐本比较，取章节索引更大者，写回本地 `Book` 记录 |
| 上传 | 章节切换、退出阅读界面时更新聚合文件对应条目并上传 |
| 反馈 | 有实际变更时提示「已同步 N 本书进度」；无变更时不打扰 |
| 手动入口 | 书架下拉刷新触发同步（复用现有刷新手势） |
| 迁移 | 首次升级时把旧的「每本一个文件」格式合并为聚合文件，完成后保留旧文件不再读写 |

### 阶段 B：扩展数据（已完成）

| 数据 | 存储 | 合并策略 | 状态 |
|---|---|---|---|
| 阅读设置 | `readConfig.json` + `shareReadConfig.json` | 以文件修改时间判新旧，云端更新则覆盖本地并重新加载 | ✅ |
| 书签 | `syncData.json` 内 | 按 `书名\|作者\|章\|位置` 去重，只增不删 | ✅ |
| 书架分组 | `syncData.json` 内 | 按 `groupId` 去重，只增不删 | ✅ |
| 书源 | `syncData.json` 内 | 按 `bookSourceUrl` 去重，只增不删 | ✅ |

同步入口：`syncData.json`（分组/书签/书源）与排版文件在**启动**和**书架下拉刷新**时同步；切到书架只对齐阅读进度，避免频繁传输大文件。

## 非目标

- 不同步书籍文件本身（TXT/EPUB 内容）。
- 不做实时长连接推送（电纸书续航优先）。
- 不改变 WebDav 账号与目录结构的基本约定。

## 验收标准

| 编号 | 标准 | 状态 |
|---|---|---|
| AC-1 | 平板读到第 100 章并退出，手机冷启动后书架显示该进度，点开续读 | ✅ 实测通过 |
| AC-2 | 手机读到更后章节后，平板启动同步能跟上 | ✅ 机制对称（与 AC-1 同一路径） |
| AC-3 | 本地进度比云端更靠后时，同步不回退 | ✅ 下载侧 `applyTo` 与上传侧 `pushProgress` 双向判断 |
| AC-4 | 章节切换后上传成功，另一设备能取到 | ✅ `saveRead` 中章节变更即上传 |
| AC-5 | 无网络时进度变更不丢，网络恢复后补传 | ✅ 实测通过（离线队列 + 网络恢复自动补传） |
| AC-6 | 首次升级时旧格式进度被完整迁移 | ✅ 实测迁移 58 本 |
| AC-7 | 同步有变更时提示，无变更不打扰 | ✅ 提示「已同步 N 本书的阅读进度」 |

补充说明：AC-5 已补齐。断网或上传失败时进度写入本地待推送队列（`files/pending_progress.json`），
网络恢复（`NetworkChangedListener`）、启动同步、手动刷新时自动补传；同一本书只保留最靠后的一条。

实测记录（详见 `docs/evidence/eink-only-check.txt` 的 [18]、[18b]）：

- 聚合文件请求数由 58+ 次降为 3 次
- 迁移 58 本书成功
- 《绍宋》阅读器翻页 4/18 → 5/18 后退出，云端 `pos` 697 → 1620；手机冷启动打开显示 8/31 26.0%，与阅读器 26.0% 一致

## 风险

- 单文件随书架增长变大（100 本约 30 KB，可接受；千本级需分片）。
- 两台设备同时上传可能互相覆盖；交替使用场景下影响有限。
- 迁移过程若中断，需保证旧文件不被删除，可重试。
