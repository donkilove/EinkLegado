# WebDav 同步 v2：聚合进度同步与多数据同步

状态：进行中
创建：2026-11-21

## 目标

解决三件事：

1. **打开 App 就能续读**：不再需要逐本进入阅读界面才同步。打开 App、切到书架、或手动刷新时，一次性对齐所有书的阅读进度，点开任何一本直接续读。
2. **进度不丢**：章节切换、退出阅读界面都触发上传；网络恢复时补传。
3. **同步范围扩大**：阅读设置、书签、书架分组、书源一并同步，换设备后不用整包备份恢复。

## 冲突规则

**取最远位置**（与用户实际需求一致）：

- 同一本书比较 `durChapterIndex`，更大者胜；章节相同则比较 `durChapterPos`。
- 进度只前进、不后退。
- 云端更新的进度在同步时**静默应用**到本地图书记录，不弹窗询问。

## 范围

### 阶段 A：进度聚合（本次）

| 项 | 设计 |
|---|---|
| 存储 | 单一 `progress.json`，内含所有书的进度条目 |
| 下载 | 启动 / 切到书架 / 手动刷新时各触发一次，一次请求拿全量 |
| 合并 | 逐本比较，取章节索引更大者，写回本地 `Book` 记录 |
| 上传 | 章节切换、退出阅读界面时更新聚合文件对应条目并上传 |
| 反馈 | 有实际变更时提示「已同步 N 本书进度」；无变更时不打扰 |
| 手动入口 | 书架下拉刷新触发同步（复用现有刷新手势） |
| 迁移 | 首次升级时把旧的「每本一个文件」格式合并为聚合文件，完成后保留旧文件不再读写 |

### 阶段 B：扩展数据（后续）

| 数据 | 存储 | 说明 |
|---|---|---|
| 阅读设置 | `settings.json` | 字体、行距、边距、主题等全局配置，单文件 |
| 书签 | 随进度聚合文件内嵌或独立文件 | 体积小，变化中等 |
| 书架分组 | `groups.json` | 分组名与顺序 |
| 书源 | `bookSource.json` | 体积大，按需同步而非每次 |

## 非目标

- 不同步书籍文件本身（TXT/EPUB 内容）。
- 不做实时长连接推送（电纸书续航优先）。
- 不改变 WebDav 账号与目录结构的基本约定。

## 验收标准

- AC-1：平板读到第 100 章并退出，手机冷启动后书架上该书进度显示第 100 章，点开直接从第 100 章继续。
- AC-2：手机读到第 120 章后，平板启动同步，进度变为第 120 章。
- AC-3：本地进度比云端更靠后时，同步不会回退本地进度。
- AC-4：章节切换后上传成功，另一设备启动能取到新进度。
- AC-5：无网络时进度变更不丢，网络恢复后自动补传。
- AC-6：首次升级时旧格式进度被完整迁移，不出现进度清空。
- AC-7：同步有变更时给出一句提示，无变更时不打扰。

## 风险

- 单文件随书架增长变大（100 本约 30 KB，可接受；千本级需分片）。
- 两台设备同时上传可能互相覆盖；交替使用场景下影响有限。
- 迁移过程若中断，需保证旧文件不被删除，可重试。
